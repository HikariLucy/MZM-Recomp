## ARM → Thumb handoff

The startup code is ARM:

```text
0x08000000  b 0x080000C0
...
0x080000EC  bx r1
```

The literal used for `agbmain` is:

```text
agbmain_ptr = 0x0800023D
```

The low bit is set, so `BX` enters `agbmain` in **Thumb state** at aligned code address `0x0800023C`.

This is an important early interworking requirement for the future GBARecomp configuration.

## IRQ path

`IntrMain` begins at `0x08000104` in ARM state. Startup initially installs a ROM pointer to this handler, while later MZM initialization copies the handler into IWRAM through `LoadInterruptCode()`.

That means MZM has at least one confirmed ROM→RAM executable-code path before static-recompilation work begins.

## Current interpretation

M0.3 has established that the decomp ELF/map can serve as a reliable semantic oracle for the verified USA ROM. ISA-state classification is now automated through ARM ELF mapping symbols (`$a`, `$t`, `$d`), and the generated CSV maps ROM addresses to ISA, symbol, object, and source path.

## HALT / VBlank anchor

The main loop's wait point is now pinned exactly:

```text
0x0800066C  THUMB  SVC 2   ; SYS_Halt
```

The surrounding loop checks `gVBlankRequestFlag` and branches back to the same `SVC 2` until the VBlank request bit becomes set. This establishes the exact semantic boundary that the runtime must reproduce for HALT wake-up behavior.

VBlank callback infrastructure:

| Address | ISA | Symbol | Role |
|---|---|---|---|
| `0x08000A98` | THUMB | `CallbackCallVblank` | invokes current VBlank callback and records VBlank request/interrupt state |
| `0x08000AE4` | THUMB | `CallbackSetVblank` | installs current VBlank callback |
| `0x080007C4` | THUMB | `SoftResetVBlankCallback` | initial boot/reset VBlank callback |
| `0x0800C894` | THUMB | `VBlankCodeInGameLoad` | in-game loading VBlank callback |
| `0x0800CA6C` | THUMB | `VBlankCodeInGame` | regular in-game VBlank callback |
