# M0.3 Evidence — Initial Semantic Map

**Date:** 2026-09-28  
**State:** **EXPERIMENTAL / IN PROGRESS**

## Purpose

M0.3 turns raw GBA addresses into useful engineering context:

```text
ROM address → ARM/Thumb state → symbol → decomp source/object → role
```

The rebuilt `mzm_us.elf` and `mzm_us.map` are used because M0.2 proved that they correspond byte-for-byte to the verified USA cartridge target.

The initial unfiltered `nm` export contains **23,503 defined symbols**.

The reproducible semantic-map script filters to the ROM address range and produced:

```text
ROM-range symbols: 21,082

```

This distinction is expected: the first number includes defined symbols outside the ROM range, while the semantic CSV intentionally focuses on cartridge-addressable metadata.

## ARM → Thumb handoff

The startup code is ARM:

```text
0x08000000  b 0x080000C0
...
0x080000EC  bx r1
```

The literal used for `agbmain` is:

```text
agbmain_ptr = 0x0800023D
```

The low bit is set, so `BX` enters `agbmain` in **Thumb state** at aligned code address `0x0800023C`.

This is an important early interworking requirement for the future GBARecomp configuration.

## IRQ path

`IntrMain` begins at `0x08000104` in ARM state. Startup initially installs a ROM pointer to this handler, while later MZM initialization copies the handler into IWRAM through `LoadInterruptCode()`.

That means MZM has at least one confirmed ROM→RAM executable-code path before static-recompilation work begins.

## Current interpretation

M0.3 has established that the decomp ELF/map can serve as a reliable semantic oracle for the verified USA ROM. ISA-state classification is now automated through ARM ELF mapping symbols (`$a`, `$t`, `$d`), and the generated CSV maps ROM addresses to ISA, symbol, object, and source path.

M0.3 remains **in progress** only because the remaining required semantic anchors for HALT/VBlank and intro/title/file-select still need to be captured and recorded.
