# M4.1 Evidence — SRAM Save Round-trip

**Date:** 2026-09-28  
**State:** **CONFIRMED / PASSED**

## Purpose

Validate that a save produced by MZM-Recomp survives process shutdown and can be loaded again into gameplay under strict-static enforcement.

## Source save

The M3 strict-static gameplay session produced:

```text
size=32768 bytes
SHA-256=471f0af7a3b315f8ac39b7185e157e6f3fe4ef70be165961a986eaab6ede3c67
```

A byte-identical evidence copy was retained locally before reload.

The operator selected the existing save and returned to gameplay successfully.

## Save after reload

After the reload session:

```text
size=32768 bytes
SHA-256=ea77daab8a62852b041259f22230e11d1cd583b9a9596cb76d525d1f70843678
```

The post-reload hash differs from the pre-reload evidence copy. This does **not** indicate failure: the in-game save loaded correctly and the runtime may legitimately persist changed SRAM state during/after the session.

The project therefore records behavioral round-trip success, not byte-stability of the entire save image.

## Verdict

**M4.1 SRAM save round-trip: PASSED.**

Confirmed for the exercised USA route:

```text
Save Room write
→ process exit
→ new strict-static process
→ existing save recognized
→ load
→ gameplay restored
```

with:

```text
dispatch_misses=0
interpreted_insns=0
unmapped=0
io_unhandled=0
```

This validates the basic SRAM write/reload lifecycle. Broader slot-copy/erase/corruption handling and cross-implementation interchange remain compatibility work.
